# S1/X4 动态任务说明

## Episode 与 Step

一个 S1/X4 Case 是一条完整动态决策序列。Episode definition 在生产时冻结完整 H 个请求；Episode trajectory 由某个 DUT/reference policy 实际运行后产生。DUT 每一步只看当前请求；未来请求不可见。

每 Step 固定执行顺序：推进到当前 arrival_time → 释放所有到期连接 → 形成当前真实频谱状态 → 生成当前 Step prompt → DUT 决策 → Validator → 合法 ACCEPT 更新资源 → 计算 post-decision Network EFM → 下一 Step。

## S1

候选路径由 deterministic KSP 得到；对规定 K 条路径穷举所有当前可行 `(path_rank, slot_start)`。公开 prompt 只对连续 slot_start 做闭区间无损压缩，不做候选动作截断。

## X4

不公开候选路径/动作。ACCEPT 必须给出 `path_node_ids`、`path_link_ids` 与 `slot_start`；Validator 检查有向路径、simple path、端点、节点/链路一致性、连续 required_slots、同一 slot_start 以及频谱边界。

## 指标

主指标为 RBR=`blocked_count/H`。只有被 Validator 接受且实际完成资源分配的 ACCEPT 计为 established；REJECT、格式错误、非法/不可行 ACCEPT 均计阻塞。次指标为 Mean Network EFM；不与 RBR 加权合成为单一总分。
