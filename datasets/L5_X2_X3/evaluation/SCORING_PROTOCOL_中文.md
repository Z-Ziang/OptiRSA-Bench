# X2/X3 评分协议

本包保持源 Case、英文系统提示词、用户题面、真值和冻结科学 Validator 的内容。Inspect AI 负责模型调用、日志和运行组织，模型正确性由本项目的 Validator 判断。评分器在收到答卷后才读取 private，模型输入仅由 public/system_prompt.txt 和 public/user_prompt.txt 构成。Sample.target 为空，不把参考答案或真值作为模型上下文。默认评测不向模型提供工具、文件访问或检索能力。

## 冻结目标与约束

- X2：自主选择完整有向路径与连续频谱；先最小化路由跳数，再最小化分配后的 WUFR。
- X3：同时接纳整个请求组或整体拒绝；先最小化新增总频谱占用量 ΔTSO，再最小化分配后的 WUFR。ΔTSO 为各请求所需槽数乘其路径跳数之和。
- 有向连通、源宿一致、连续且同起始槽、既有资源不冲突、X3 新请求之间不冲突，均按冻结 Validator 检查。w 是源 Case 的完整所需槽数，不额外增加 guard。
- X2/X3 均不限于 K 条预生成候选路径；不能替换成 K-limited 求解。
- 原英文输入不提供 WUFR 公式。评分程序保留准确实现，仅供评测端调用。该协议必须在论文中披露，不能称为向模型完整公开二级指标定义。

## 有解 Case 的四类结果

| category | 中文 | 判定 |
|---|---|---|
| CORRECT | 最优正确 | 满足约束并达到源认证的词典序最优值；同值的不同分配也可正确 |
| SUBOPTIMAL | 可行次优 | 分配合法，但一级目标或同一级目标下的二级目标较差 |
| INFEASIBLE | 不可行 | JSON 与 schema 合规，但路径、频谱或联合约束不满足 |
| MISSING | 缺失合规解 | 无合规 JSON/schema，或有解时主动 REJECT 而没有返回合法分配 |

无解 Case 另列数量、正确拒绝数和错误接纳数。正确 REJECT 在总答题类别中记 CORRECT，result_kind=CERTIFIED_REJECT，不计成“求得最优分配”。服务超时、网络/API 错误、上下文不支持与程序评分异常单独记录，不能计成模型不可行答卷。REVIEW_DATA/REVIEW_ORACLE 也不计入正确率分母。

默认只去除包住整份回答的一层 JSON/普通代码围栏；不会从解释文字中搜索 JSON，不修补字段，不丢弃非法分配，不重新让模型作答。strict 字段同时保留完全不去围栏的诊断结果，原始回答完整保留。

冻结 Validator 的 WUFR 数值容差为 1e-12；外层四分类沿用现有本机评测程序的 gap 分类容差 1e-9。一级 hop/ΔTSO 为整数，不存在通过此容差接受较差一级目标的情况。指标原值与 gap 均保留，不能隐藏正 gap 或将“可行”写为“最优”。若合法答案优于存储最优值，标记 REVIEW_ORACLE，不能将其直接算错。

## 接口与证据等级

来源记录的数据证据合格与正式 LLM 接口准入是两件事。本包保留 interface_status=REVIEW_OBJECTIVE_DEFINITION，默认 --purpose exploratory 可运行现有冻结题面的探索性评测。--purpose formal 遇到待审接口会停止；此构建没有擅自批准接口或将原提示词升级。

构建完成了全部 Case 的文件绑定、公开题面/图/资源位图/请求对应检查，以及参考解可行性和一级目标检查；已有源 Validator PASS 与精确认证记录随 Case 保留。构建中的有界完整 Validator 复评分及 Inspect 离线验收记录另见 verification。没有重新独立求解全池的全局最优，没有把软件离线验收称为模型实验。

统计必须同时给出计划数、已收到答卷数、可评分数、四分类、无解正确拒绝、服务错误、REVIEW、Token/时延。不同模型正式比较应使用同一 Case 清单与提示词；相同拓扑/初态/请求家族不能当成彼此完全独立的样本。
