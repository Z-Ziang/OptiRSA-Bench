你需要完成弹性光网络中的并发业务请求的路由与频谱联合分配任务。你将得到：当前网络有向拓扑、当前每条有向链路的频谱资源状态、一组待资源分配的并发业务请求意图。请你对每个 case进行判断：可否基于现有网络信息，同时完成全部业务请求的资源分配、建立全部业务连接，并输出该组业务请求的联合资源分配方案。

如果全部业务能够建立，你需要为每一项业务请求选择一条从其源节点到目的节点的合规有向路径，并在该路径经过的所有有向链路上分配同一段连续的满足该业务请求所需的频谱槽位。

分配必须同时满足：
每项业务请求所分配路径中的有向链路首尾连续；
每项业务请求所分配路径从该业务请求的源节点开始，到目的节点结束；
对于每项业务请求，在其路径的所有链路上，分配的槽位区间均为空闲；
对于每项业务请求，在其路径的所有链路上，分配的初始频谱槽位序号相同；
对于每项业务请求，在其路径的所有链路上，分配的连续槽位数量均等于该业务请求的频谱槽位需求数；
不同业务请求之间，如果经过相同的有向链路，则它们在该有向链路上分配的频谱槽位区间不能发生重叠；
必须对该组并发业务请求进行联合资源分配。只有全部业务请求均能够同时完成资源分配时，才能建立该组业务连接；如果无法同时为全部业务请求完成资源分配，则拒绝该组业务请求。

网络信息：
规定网络中每条链路包含固定数量的频谱槽位，数量固定为320，槽位编号范围为0至319。
[a,b] 表示从槽位 a 到槽位 b 的连续区间，区间两端均包含在内。一条链路上的完整槽位编号为[0,1,2,...,319]。

当前网络信息采用以下格式进行表示：

每一条有向链路的信息：
有向链路<link_id>：<source_node_id>→<destination_node_id>；空闲槽位区间：[a,b],[c,d],...。

其中，link_id 为有向链路编号；source_node_id→destination_node_id 表示该链路的传输方向；[a,b] 表示编号从 a 到 b 的连续空闲频谱槽位区间，a 和 b 均包含在区间内；多个区间之间使用逗号分隔。若一条链路当前没有任何空闲槽位，则写为“空闲槽位区间：无”。每一行同时完整描述该有向链路的连接关系和当前频谱资源状态。

路径采用节点数组和有向链路数组共同表示。若路径节点数组为 [3,7,12,18]，有向链路数组为 [18,41,57]，则依次表示节点 3→7→12→18，其中链路18连接3→7、链路41连接7→12、链路57连接12→18。

优化目标包括：
在满足全部并发业务请求可行联合资源分配的前提下，优先选择并发业务请求完成资源分配后所占用的总槽位数最小的资源分配方案（最小化总槽位数）。
在满足全部并发业务请求可行联合资源分配的前提下，优先选择使资源分配后的全网频谱碎片程度最小的资源分配方案（最小化频谱碎片程度）。
其中，并发业务请求完成资源分配所占用的总槽位数等于全部业务请求的槽位数之和，对于每一项业务请求，其槽位数等于该业务请求的频谱槽位需求数乘以其分配路径的跳数。

输出要求：
资源分配方案的输出内容包括：
1.该组并发业务请求的资源分配决策（即decision，包括建立全部请求连接，即ACCEPT，或拒绝该组请求，即REJECT）；
2.当建立全部请求连接时：在联合资源分配方案allocations中输出每一项业务请求的编号request_id、分配的路径节点数组path_node_ids、分配的有向链路数组path_link_ids、分配的起始槽位序号slot_start；
3.当拒绝该组请求时：联合资源分配方案的allocations为空数组。
输出内容请只返回一个JSON对象，代表该组并发业务请求的联合资源分配方案，请你务必按照以下格式输出：
{
  "decision": "",
  "allocations": [
    {
      "request_id": "",
      "path_node_ids": [],
      "path_link_ids": [],
      "slot_start": 0
    }
  ]
}
