You need to complete a routing and spectrum assignment task for a single service request in an elastic optical network. You will be given: the current directed network topology, the current spectrum resource state of each directed link, and one service request intent awaiting resource assignment. For each case, determine whether the service request can be assigned resources and its service connection can be established based on the current network information, and output the resource assignment plan for the service request.

If the service can be established, you need to select a feasible directed path from the source node to the destination node and assign the same contiguous block of spectrum slots, with a size equal to the service request's slot demand, on every directed link traversed by that path.
The assignment must satisfy all of the following conditions:
1. The directed links in the path must be consecutively connected;
2. The path must start at the source node of the service request and end at its destination node;
3. The assigned slot interval must be free on every link of the path;
4. The starting spectrum-slot index must be the same on every link of the path;
5. The number of contiguous slots assigned on every link of the path must equal the spectrum-slot demand of the service request.


Network information:
Each link in the network contains a fixed number of spectrum slots: 320 slots, indexed from 0 to 319.
[a,b] denotes the contiguous interval from slot a to slot b, with both endpoints included. The complete slot index set on one link is [0,1,2,...,319].

The current network information is represented in the following format:

Information for each directed link:
Directed link <link_id>: <source_node_id>→<destination_node_id>; free slot intervals: [a,b],[c,d],....

Here, link_id is the directed-link identifier; source_node_id→destination_node_id indicates the transmission direction of the link; [a,b] denotes a contiguous interval of free spectrum slots from index a to index b, with both a and b included; multiple intervals are separated by commas. If a link currently has no free slots, write "free slot intervals: none". Each line fully describes both the connectivity and the current spectrum resource state of that directed link.

A path is represented jointly by a node array and a directed-link array. For example, if the path node array is [3,7,12,18] and the directed-link array is [18,41,57], they represent the sequence 3→7→12→18, where link 18 connects 3→7, link 41 connects 7→12, and link 57 connects 12→18.

The optimization objectives may include:
Subject to feasible resource assignment, prefer the resource assignment plan with the minimum path hop count (minimize path hop count).
Subject to feasible resource assignment, prefer the resource assignment plan that minimizes the network-wide spectrum fragmentation after assignment (minimize spectrum fragmentation).

Output requirements:
The resource assignment plan must include:
1. The resource assignment decision for the service request (decision), including establishing the request connection (ACCEPT) or rejecting the request connection (REJECT);
2. If the request connection is established: output the assigned path node array path_node_ids, the assigned directed-link array path_link_ids, and the assigned starting slot index slot_start;
3. If the request connection is rejected: path_node_ids and path_link_ids must both be empty arrays, and slot_start must be null.
Return only one JSON object representing the resource assignment plan for the service request. You must follow the format below exactly:
{
  "decision": "",
  "path_node_ids": [],
  "path_link_ids": [],
  "slot_start": 0
}
Example:
For a service request whose connection is established, output:
{
  "decision": "ACCEPT",
  "path_node_ids": [3, 7, 12, 18],
  "path_link_ids": [18, 41, 57],
  "slot_start": 23
}

For a request whose connection is not established, output:
{
  "decision": "REJECT",
  "path_node_ids": [],
  "path_link_ids": [],
  "slot_start": null
}
