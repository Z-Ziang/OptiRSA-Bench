你需要完成动态弹性光网络中的候选动作下的序贯资源分配任务。你会得到一条由多个按时间连续到达的业务请求组成的动态决策序列。每一步只处理当前到达的一个业务请求，未来请求不会提前公开。
在每个业务请求到达前，你会得到当前网络的有向拓扑、每条有向链路的频谱资源状态、当前业务请求，以及该请求在规定的 K 条候选路径范围内的全部可行资源分配动作。
在每个业务请求到达时，环境首先释放所有已到达释放时刻的已有连接，然后向你提供当前网络状态并进行本步决策。若当前请求被 ACCEPT，所分配的频谱资源将从当前到达时刻起被占用，并在该请求的 holding_time 结束后释放；若输出 REJECT，本请求不会占用新的频谱资源。未来业务请求仍不会提前公开。
每一个可行资源分配动作由候选路径编号 path_rank 和频谱起始槽位 slot_start 组成。对于同一条候选路径，当存在多个连续可行的 slot_start 时，会采用列表展示，例如slot_start∈[1,3] 表示 slot_start=1、2、3 均分别构成一个可行资源分配动作，区间两端均包含在内，多个可行区间之间使用逗号分隔。每一个区间中的每一个整数 slot_start 与对应的 path_rank 共同表示一个独立的可行资源分配动作。你不需要自行搜索新的路径或频谱位置，也不能选择公开候选动作集合之外的资源分配方案。

网络信息：规定网络中每条链路包含固定数量的频谱槽位，数量固定为320，槽位编号范围为0至319。[a,b] 表示从槽位 a 到槽位 b 的连续区间，区间两端均包含在内。一条链路上的完整槽位编号为[0,1,2,...,319]。
当前网络信息采用以下格式进行表示：
每一条有向链路的信息：有向链路<link_id>：<source_node_id>→<destination_node_id>；空闲槽位区间：[a,b],[c,d],...。
其中，link_id 为有向链路编号；source_node_id→destination_node_id 表示该链路的传输方向。若一条链路当前没有任何空闲槽位，则写为“空闲槽位区间：无”。每一行同时完整描述该有向链路的连接关系和当前频谱资源状态。
路径采用节点数组和有向链路数组共同表示。若路径节点数组为 [3,7,12,18]，有向链路数组为 [18,41,57]，则依次表示节点 3→7→12→18，其中链路18连接3→7、链路41连接7→12、链路57连接12→18。

你需要根据当前网络状态和当前业务请求，从给出的全部可行候选动作中选择一个资源分配方案。当存在至少一个可行候选动作时，你必须尽量选择其中一个并建立当前业务连接；当不存在任何可行候选动作时，输出 REJECT。
你的目标是在整条动态决策序列中，根据不断变化的网络资源状态持续选择合适的资源分配方案。首要目标是在整个动态决策序列中尽量减少被阻塞的业务请求，即尽量提高成功建立数量。次要目标是在不违背首要目标的基础上，尽量降低网络外部频谱碎片程度（External Fragmentation Metric，EFM）。不同候选动作虽然都能够成功建立当前业务，但会形成不同的后续网络资源状态，因此你需要综合考虑当前资源分配对后续业务请求的长期影响。
你的输出有严格的格式要求，请你只返回一个 JSON 对象，且务必采用以下格式输出，不要输出额外解释。
当业务请求建立时，输出格式示例：
ACCEPT：
{
  "decision": "ACCEPT",
  "path_rank": 1,
  "slot_start": 0
}
当业务请求无法建立时，输出格式示例：
REJECT：
{
  "decision": "REJECT",
  "path_rank": null,
  "slot_start": null
}
