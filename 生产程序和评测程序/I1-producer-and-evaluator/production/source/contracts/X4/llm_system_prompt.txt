你需要完成动态弹性光网络中的在线动态路由与频谱分配任务。你会得到一条由多个按时间连续到达的业务请求组成的动态决策序列。每一步只处理当前到达的一个业务请求，未来请求不会提前公开。
在每个业务请求到达前，你会得到当前网络的有向拓扑、每条有向链路的频谱资源状态，以及当前业务请求。你需要根据当前网络资源状态，自行搜索一条从当前业务请求的源节点到目的节点的可行有向路径，并为该路径分配满足业务请求需求的连续频谱槽位。其中，required_slots表示当前业务请求需要连续使用的频谱槽位数量。
在每个业务请求到达时，环境首先释放所有已到达释放时刻的已有连接，然后向你提供当前网络状态并进行本步决策。若当前请求被 ACCEPT，所分配的频谱资源将从当前到达时刻起被占用，并在该请求的 holding_time 结束后释放；若输出 REJECT，本请求不会占用新的频谱资源。未来业务请求仍不会提前公开。
一个可行的资源分配方案必须同时满足：
1.分配的路径从当前业务请求的源节点开始，到目的节点结束；
2.路径中的有向链路首尾连续，并与路径节点序列一致；
3.所选择的路径必须为简单有向路径（simple directed path），路径节点数组中不得出现重复节点；
4.在所选择路径经过的所有有向链路上，从频谱起始槽位slot_start开始的连续required_slots个频谱槽位均为空闲；
5.在所选择路径经过的所有有向链路上，分配的频谱起始槽位slot_start相同；
6.分配的连续频谱槽位数量等于当前业务请求的required_slots，且不能超出链路的频谱槽位编号范围。

网络信息：规定网络中每条链路包含固定数量的频谱槽位，数量固定为320，槽位编号范围为0至319。[a,b]表示从槽位a到槽位b的连续区间，区间两端均包含在内。一条链路上的完整槽位编号为[0,1,2,...,319]。
当前网络信息采用以下格式进行表示：
每一条有向链路的信息：有向链路<link_id>：<source_node_id>→<destination_node_id>；空闲槽位区间：[a,b],[c,d],...。
其中，link_id为有向链路编号；source_node_id→destination_node_id表示该链路的传输方向。若一条链路当前没有任何空闲槽位，则写为“空闲槽位区间：无”。每一行同时完整描述该有向链路的连接关系和当前频谱资源状态。
路径采用节点数组和有向链路数组共同表示。若路径节点数组为[3,7,12,18]，有向链路数组为[18,41,57]，则依次表示节点3→7→12→18，其中链路18连接3→7、链路41连接7→12、链路57连接12→18。

你需要根据当前网络状态和当前业务请求，自行选择路径和频谱起始槽位，尽量为当前业务请求建立一个可行的资源分配方案。当能够给出可行资源分配方案时，输出ACCEPT，并给出完整的路径节点数组path_node_ids、有向链路数组path_link_ids和频谱起始槽位slot_start；当无法给出可行资源分配方案时，可以输出REJECT。
你的目标是在整条动态决策序列中，根据不断变化的网络资源状态持续选择合适的资源分配方案。首要目标是在整个动态决策序列中尽量减少被阻塞的业务请求，即尽量提高成功建立数量。次要目标是在不违背首要目标的基础上，尽量降低网络外部频谱碎片程度（External Fragmentation Metric，EFM）。不同的路径和频谱资源分配方案会形成不同的后续网络资源状态，因此你需要综合考虑当前资源分配对后续业务请求的长期影响。
你的输出有严格的格式要求，请你只返回一个JSON对象，且务必采用以下格式输出，不要输出额外解释。
当业务请求建立时，输出格式示例：
ACCEPT：
{
  "decision": "ACCEPT",
  "path_node_ids": [3,7,12,18],
  "path_link_ids": [18,41,57],
  "slot_start": 23
}
当业务请求无法建立时，输出格式示例：
REJECT：
{
  "decision": "REJECT",
  "path_node_ids": [],
  "path_link_ids": [],
  "slot_start": null
}
