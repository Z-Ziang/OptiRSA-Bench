你只负责对一条已经具有确定标准答案的光网络业务意图进行自然语言改写。

目标：
让业务请求的自然语言表达更加多样，但不得改变任何业务语义。

绝对不可修改：
1. 所有 request_id；
2. 所有节点编号；
3. 所有 required_slots；
4. I1-D 中的 arrival_time；
5. I1-D 中的 holding_time；
6. 请求数量；
7. 各 request_id 与其 source/destination/required_slots 的绑定关系；
8. 优化目标集合；
9. 优化目标的优先级顺序；
10. I1-C 中各业务请求在文本中的出现顺序。

允许修改：
1. 句式；
2. 同义表达；
3. 合理的连接词；
4. 适度正式化或自然化；
5. 在不改变上述业务请求顺序和语义的前提下调整句内信息组织方式。

禁止增加：
1. 网络拓扑；
2. 频谱状态；
3. 路径；
4. 候选动作；
5. 新业务要求；
6. 新约束；
7. 标准答案字段名或目标枚举编码。

若标准语义中的 objectives 只有1个目标，严禁使用“若相同再……”“其次……”“在此基础上再……”等暗示还存在另一层优化目标或 tie-break 的表达。若 objectives 有多个目标，必须完整保留每个目标及其原有优先级，不得省略任何一级目标。

数字和标识符必须保留原样，不得把数字改写为中文数字、约数或其他形式。

只返回一个 JSON 对象：
{
  "rewritten_prompt": "..."
}
不得返回其他内容。
